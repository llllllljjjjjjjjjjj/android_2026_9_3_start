# 断言设计（针对工作流 D 的有效性）

## 设计原则

断言必须**客观可验**（可从产出文件中机械判定），且**能区分两个版本**。
由于本环境子代理不可用、由我代跑，评分侧重**客观行为特征**而非主观质量。

## 用例 0：search-chain-fullflow

| ID | 断言 | 检查方式 | 期望差异 |
|---|---|---|---|
| A1 | 产出含**七层链路结构**（触发/参数/前置特征/签名/传输/响应/回执） | 检查文件中出现 7 个层次关键词 | with ✓ / old ✗ |
| A2 | 产出含**前置接口表**（业务请求之前必须发生的请求） | 检查是否列出 `history_words_record` 并标注"前置" | with ✓ / old ✗ |
| A3 | 产出含**紧邻特征上报表** | 检查是否列出 `upload_ei_feature` 并标注"紧邻/配对" | with ✓ / old ✗ |
| A4 | 产出含**配对强度**标注（强/中/弱） | 检查是否出现"配对强度"或"强"标注 | with ✓ / old ✗ |
| A5 | 产出含**因果验证表**（阻断实验设计） | 检查是否有"阻断/因果/实验设计"表 | with ✓ / old ✗ |
| A6 | 产出含**降级分级判据**（OK/软降级/硬拒绝） | 检查是否区分三级 | with ✓ / old ✗ |
| A7 | 缺证据处标 `[未知]`/`[未证]` 而非编造 | 检查是否使用不确定标记 | with ✓ / old 部分 |
| A8 | 断言"配对校验"时**区分时序相关与因果** | 检查是否把无实验结论标为"推测" | with ✓ / old ✗ |

## 评分口径

- **pass** = 产出文件中能找到对应内容且非敷衍（有具体证据引用）
- **fail** = 缺失，或仅提及关键词但无实质内容
- 每断言权重相同；pass_rate = passed / total
