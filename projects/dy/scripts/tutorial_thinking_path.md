# 从零逆向「八神签名」：一条完整的思考路径

> 受众：学安卓逆向约 1 个月的人（会 adb / jadx / frida 基本操作，缺的是方法论）
> 案例：抖音 38.0.0 的八神签名（x-argus / x-gorgon / x-helios / x-khronos / x-ladon / x-medusa）
> 本文教「怎么想」，不是「结论是什么」。结论在 `../docs/signature_structure.md`。
>
> 一条贯穿全文的原则：**逆向不是看代码，是做实验。每一步都要有可验证的假设，每一个结论都要被数据推翻过一次以上才算数。**

---

## 0. 先想清楚：我要攻什么？

新手拿到「逆向八神」这种任务，第一反应往往是打开 jadx 搜 `x-argus`。**先别急**。

**思考路径第 1 步：把目标拆成可验证的命题。**

「八神」是个模糊词。拆开看：它是 7 个 HTTP 请求头（X-Argus、X-Gorgon……），由客户端生成、服务端校验。那么任务 = 回答三个问题：

1. **这些头在哪里生成？**（定位问题）
2. **用什么算法生成？**（还原问题）
3. **我怎么证明我搞对了？**（验证问题——它决定前两个问题何时算"做完"）

第三问最重要，也最常被新手跳过。**动手前先定义验证标准**：如果我说"X-Argus 破解了"，什么证据能证明？——答案是：用 100+ 组随机输入，我自己的 Python 实现和真机输出**逐字节相同**。这就是本项目铁律 SF-012。如果你发现自己回答不了第三问，说明第一、二问也还没想清楚。

---

## 1. 找入口：从「写头的地方」追到「生成头的地方」

### 1.1 字符串是混淆世界的地图

打开 APK（先判断有没有壳——jadx 一打开只有几十 KB 空壳类就是加固了，本项目 59 个完整 dex = 无壳）。搜什么？**搜字符串 `x-argus`**。

为什么？因为 ProGuard/R8 混淆**不改字符串字面量**——类名可以变成 a.b.c，但 `"x-argus"` 永远长那样。字符串是你在混淆代码里的锚点。

搜到 libsscronet.so 0x4127ac 一带（native 层的头名构建函数），顺手 hook 抓到了完整八神。**第一次小成功**。

### 1.2 关键教训：写头 ≠ 生成头

追写入链时，我把目标锁定在 `sub_47A31C`——反汇编后发现它只是**流量控制入口**，签名是从它内部这一行出去的：

```
BLR X23(X0=str1, X1=str2)   ; 调用全局指针 X23，返回 char*
```

**思考路径第 2 步：调用链上每一层都要问「这是终点还是中转站？」**

判断方法：这个函数里有没有看到"生成"的动作？47A31C 没有——它拿到返回串后只是解析、拆分、写进 header 容器（sub_2ED608 解析 → SetHeader 写入）。真正生成的是 X23 指向的东西。

`X23` 来自全局变量 `qword_5FFE80`。静态看不出来指向哪，**那就运行时读**：hook 时打印它的值 → `libmetasec_ml.so + 0x28065c`。这才是八神生成器。

> 新手错误姿势：对着 47A31C 一行行啃汇编，啃三天也找不到签名算法——因为它根本不在那。**BLR/BR Xn 间接调用必须追指针值，不能停在函数名上。**

### 1.3 为什么这一步花了 6 轮 hook？

因为链路上有 5 层：请求拦截 → 回调注册 → metasec 注册 → 生成 → 写回。每层都要验证「我 hook 的点真的在被调用、参数真的是我想要的」。**hook 不是装上就算赢，要看到输入输出对上号**。

## 2. 静态 vs 动态：两条腿走路

### 2.1 先看数据区，不要啃代码

28065c 是重度混淆的（OLLVM 状态机 + VMP + 加密指针 + XOR 字符串）。新手看到这种代码会硬着头皮读——**停**。

**思考路径第 3 步：混淆代码里最诚实的是字符串和数据区。**

我把 SO 从内存 dump 出来（运行中的 rwxp 页 + bss 页合并——为什么要 dump？因为加密/加固的 SO 在运行时才会解密自身），丢进 IDA 批量反汇编。第一件事不是读 28065c，而是**看全局字符串区**：

- `[DouYin] RunPreInitHooks`、`https://mssdk.bytedance.com`、`http_sign_gen_all` → 这个 SO 是**字节跳动 MS SDK**，不是抖音自研

一个 hexdump 解决身份问题。**数据区看一遍的成本是分钟级，代码读一遍是小时级。**

### 2.2 静态和动态要互相印证

静态分析告诉我：282020 有个函数用 `strchr('?', '#')` 提取 URL 的 query 部分。

动态实验后来证实：Gorgon 只对 query 敏感，path/scheme/fragment 全不敏感——**和静态结果完全对上**。

**这叫做「两条独立路径指向同一结论」**。只靠静态怕 IDA 反汇编有错；只靠动态怕样本偏差。两条都对上，结论才稳。

## 3. 建立 oracle：把目标函数变成可调用的黑盒

### 3.1 Oracle 思维

**思考路径第 4 步：不要试图一次看懂整个算法。先把它变成「喂输入、拿输出」的黑盒。**

28065c 的协议已经清楚了：`char*(url, headers) → "name\r\nvalue\r\n..."`。那就在 frida 里把它包成 RPC：

```javascript
rpc.exports = {
  oracle: function (url, headers) {
    var f = new NativeFunction(base.add(0x28065c), 'pointer', ['pointer', 'pointer']);
    return f(Memory.allocUtf8String(url), Memory.allocUtf8String(headers)).readUtf8String();
  }
};
```

Python 侧就能像调 API 一样批量调用。**这 30 行代码是后续所有分析的基石**——有了它，静态逆向的每一步结论都能被动态验证。

### 3.2 三个坑的思考价值

跑通 oracle 踩了 3 个坑。**坑不是障碍，是信息**：

**坑 1：App 从 frida 进程表消失了。** `get_process()` 报错找不到进程，但 adb 看到进程活着。想想为什么：App 的反检测把进程从 frida 的枚举里**藏起来了**（但没杀进程、没杀 frida-server）。那解法就简单：绕过枚举，用 `adb shell pidof` 拿 pid 直接 `attach(pid)`。
> 思考收获：**检测到反制措施时，先分析"它防的是什么、没防的是什么"**，而不是慌。

**坑 2：RPC 方法名找不到。** 试了 snake_case、camelCase 都报错，最后发现 frida 16.5.7 的 Python 绑定把方法名**转小写后查找**。
> 思考收获：**工具行为和文档不一致时，验证工具（`dir(exports_sync)` 打印代理属性），不要怀疑自己。**

**坑 3：空 URL 返回 NULL。** App 没崩（内部有防御），只是 Python 侧没处理 None 崩了。
> 思考收获：**边界输入是免费的探测手段**——顺手试空串/超长串/非法格式，能白捡防御逻辑信息。

### 3.3 顺手捡到的新发现

`oracle('https://x/', ...)` 返回的不是八神，而是 `X-Neptune`（第 9 个头，之前没人提过）。做对照实验：合法完整 URL → 6 头；短 URL → 只有 Neptune。

**思考路径第 5 步：遇到意外的输出，立刻做最小对照实验定位触发条件。**（只变 URL、只变 headers、两者都变——3 次调用就知道分支条件是 URL 结构，与 headers 无关。）

## 4. 差分分析：让输入替你说话

拿到 oracle 后，**设计实验**而不是随机采集。112 组输入分了 6 组，每组回答一个具体问题：

| 组 | 设计 | 回答的问题 |
|----|------|-----------|
| G1 同一输入×6 | 重复调用 | 有时间依赖吗？ |
| G2 只变 URL | 控制 headers | URL 影响哪些头？ |
| G3 只变 headers | 控制 URL | headers 影响哪些头？ |
| G4 完全随机 | 泛化 | 结论是否普适？ |
| G5 边界 | 空串/超长/非法 | 边界行为？ |
| G6 真实格式 | 贴近生产 | oracle 输出和真实抓包一致吗？ |

**这是控制变量法。** 一次只改一个东西，输出的差异就是那个东西的贡献。

### Argus 的破解链（完整思考过程回放）

1. G1 看组内：Argus 6 次重复**完全相同** → 和时间无关（至少秒级内）
2. G2/G3/G4 看组间：**完全不随 url/headers 变** → 只依赖某个全局状态
3. 跨组对比发现：G1~G6 的 Argus 第 1 字节 `c8→c9→ca→cb`，而各组的 X-Khronos（时间戳）`...5000→5001→5002→5003`——**低字节完美对齐**！
4. 提出假设：Argus = 时间戳的某种编码。解码 base64 → 4 字节，第 3、4 字节 `8c 6a` 恰好是时间戳高 16 位
5. 假设精化：`X-Argus = base64(LE32(unix_ts))`——小端时间戳
6. **用程序验证，不用脑子算**：历史 8 个真实样本 + 新采 12 个跨秒样本，逐字节对比 → 20/20 全中

中间有个小插曲：我手算十六进制换算错了两次，差点否定这个假设。**教训：任何换算交给 Python，人脑只负责想方向。**

## 5. 假设被推翻的艺术：两个「漂亮的错误」

### 5.1 「每 10 次轮换」——被自己的采样方式骗了

Gorgon 有个"上下文"概念（hash 的后 13 字节组内恒定、组间变化）。批内快速采集时，切换点整齐地落在第 0→1、10→11 次调用——**看起来像每 10 次轮换一次**。

但 25 次**慢速**实验（每次调用间隔 ~100ms）切换点变成 3、6、13、17、23——完全不规则。

**思考路径第 6 步：样本的采集方式会制造假规律。任何"每 N 次"的结论，都要换采样节奏验证。**

最后用 sleep 控制实验定性：sleep 0.1s 不切换、0.25s 切换、0.4s 又不切换……真相是 **~0.5-0.6 秒的时间轮换**（App 后台活动驱动）。批内 μs 级间隔太快来不及轮换，才显得像"每 10 次"。

> 这是本文最想教的一课：**你观察到的规律，可能是你采样方式的函数。** 换节奏、换批量、换时间点再测，规律还成立才是真的。

### 5.2 十六进制手算错误——优雅地承认工具性错误

计算 Argus byte1 时我手工 hex 换算错了，一度以为公式不成立。**重新用 Python 算，公式完美成立。** 这种错误不丢人，丢人的是硬撑着不改。**让程序干所有计算活。**

## 6. 什么时候停：策略判定与止损

**思考路径第 7 步：逆向的终点不一定是"纯算法还原"。**

把八神拆完后发现：
- X-Argus：完全破解（就是时间戳编码）✅ 可离线
- X-Gorgon/Ladon/Helios/Medusa：核心在 **VMP**（虚拟机保护的字节码）+ **~0.5s 轮换的密钥**

轮换密钥意味着：就算我啃完 VMP 还原出算法，密钥每半秒换一次，离线实现必须同步密钥轮换机制——投入产出比极差。**继续啃 VMP 是给面子，不给里子。**

正确的交付形态是**在线 oracle**：App 运行 + frida RPC = 一个稳定的签名服务。这是正规军做法（本项目技能库叫"策略 E / 在线兜底"）。

**止损不是失败，是判断力。** 区分"值得啃的"和"啃了也白啃的"：
- 白啃：VMP 核心 + 轮换密钥 + 设备绑定态
- 值得啃：算法可见、密钥固定或可提取、离线可复现

## 7. 可迁移框架：给你一个新目标

下次拿到一个签名任务，脑子里的流程应该是：

```
① 定义目标与验证标准（回答"怎么算做完"）
   ↓
② 找入口：字符串锚点 → hook 抓真实样本（抓到了才算入场）
   ↓
③ 追链路：每层问"终点还是中转站"，BLR 追指针值
   ↓
④ 静态+动态互证：数据区定身份，hook 拿运行时数据
   ↓
⑤ 建 oracle：把生成函数包成 RPC 黑盒
   ↓
⑥ 差分实验：控制变量法设计输入组，让数据说话
   ↓
⑦ 验证：SF-012（100+ 随机输入字节级一致）才说"破解了"
   ↓
⑧ 策略判定：纯算 / oracle / 放弃，按投入产出比止损
```

每个环节的**思考检查点**：
- ① 我的验证标准能证伪我的结论吗？
- ② 抓到的样本是真实路径触发的吗？（不是 RPC 人造的）
- ③ 这一层是生成还是转发？
- ④ 静态和动态的结论互相印证了吗？
- ⑤ 黑盒的输入输出协议我 100% 确定吗？（用对照实验）
- ⑥ 每次只变了一个变量吗？
- ⑦ 验证覆盖了边界情况吗？
- ⑧ 继续投入的边际产出还大于零吗？

---

## 8. 新手最容易犯的 5 个错

1. **把"抓到头"当"解了算法"**——抓到 X-Argus 的生成只是起点，字节级验证过才算解
2. **一行行啃混淆代码**——先看数据区、先建 oracle、先做实验，代码是最后的手段
3. **不控制变量**——随手采 100 组随机输入，看起来很多，其实什么都推不出来
4. **相信批内规律**——切换点、计数、周期这类结论必须变节奏验证
5. **不写验证就宣布完成**——"我猜它是 md5"不叫破解，100 组字节对拍全中才叫
