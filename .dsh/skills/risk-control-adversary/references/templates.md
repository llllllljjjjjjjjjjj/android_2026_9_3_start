# 统一格式定义（Templates）

本文件是知识库的**格式契约**：三类产物（方案/项目记录/经验条目）+ 证据/置信度量化定义 + 四级标签体系 + 生命周期规则 + 零基线兜底模板 + 策略转脚本交付模板。所有写入必须遵守——格式统一是知识库跨项目复用、可检索的前提。字段缺失时写「未知」或「-」，不要删列。条目正文的操作性规则（重合判定/准入/检索/F→E 转化）在 general-principles.md §0。

## §3 经验条目格式（L1 基础原理层）

写入路径：`references/general-principles.md`。E-（成功经验）与 F-（失败经验）共用编号空间，E-01 起递增，**只增不覆盖、不重号**；写入前先读 general-principles.md §0 规则与文件确认下一个编号。

> **归属约束**：本库只写本 skill 独占维度（请求策略与行为画像、业务规则风控、设备指纹自洽/去关联）。签名/参数加密→protocol-signature-reverser；环境检测/反 Frida→android-dynamic；传输指纹→android-recon fp_stack。这些维度不写入本库。

### 3.1 证据等级与置信度（数值阈值，写入必对）

证据等级回答「有没有经过验证」，由「**复现次数 R × 样本量 N**」决定；置信度回答「信源可靠吗」，按信源分级。**两轴独立标注、互不推导**（完整语义见 general-principles.md §0.1/§0.2）：

| 证据等级 | 数值阈值 | 置信度 | 分级依据 |
|---------|---------|--------|---------|
| 已实证 | R ≥ 3 且 N ≥ 2（跨账号/IP/设备/时段 ≥2 种独立条件） | 高 | 实测抓包 / 项目实测 / 官方文档 |
| 大样本 | R ≥ 5 且 N ≥ 10，且跨 ≥2 平台/时段 | 中 | 技术社区 / 专业书籍（需交叉验证） |
| 小样本 | 1 ≤ R ≤ 2，或 N < 2 | 低 | 自媒体 / 单源 / 信息陈旧（仅作线索） |
| 推测 | R = 0，有线索（情报/静态分析/单点观察） | | |
| 未知 | 无任何证据 | | |

样本量记录格式：`<账号数>账号 × <IP/设备数> × <复现次数>`；未记录写 `-（未记录）`。升级必须跑 SKILL.md A3.5 验证闭环，达标后在条目「版本」追加记录。

> 注：置信度与证据等级**正交**——推测/未知条目同样要标置信度（如「推测 × 高」= 官方声明未实测，强线索；「推测 × 低」= 自媒体线索）。上表置信度列仅为常见对应，不是推导关系。

### 3.2 合并 / 补充 / 生命周期规则

- **核心原理重合判定**（判定对象 = E:「检测原理+对抗思路」/ F:「触发条件+根因」二元组；三级判定：完全重合→追加 / 部分重合→变体或新增互补 / 不重合→新增）与合并、补充行格式：见 general-principles.md §0.3；
- **生命周期**：失效状态（生效 / 待验证 / 已作废）、版本号 v1.0 起每次补充/修正 +0.1、冲突仲裁优先级（证据等级 > 信源 > 时间）：见 general-principles.md §0.8；
- **F→E 转化**与失败影响分级（致命/严重/一般）：见 general-principles.md §0.9。

## §5 零基线兜底模板（资料极薄场景起步用）

资料几乎为零时，直接套以下保守默认值起步，边跑边对拍调参，不空等资料。

| 参数 | 默认值 | 说明 |
|------|--------|------|
| 请求间隔 | 1-3s 随机（`random.uniform`） | 保守起步，实测无风控后逐步提速 |
| 批量大小 | 单次 ≤10 条 | 贴频控阈值前先对拍 |
| 头伪装 | 全套浏览器头集群随机轮换 | UA/Accept-Language/Accept-Encoding/Referer |
| 会话 | 先首页→列表→详情，带 Referer | 不直连深链 |
| 代理 | 高匿名代理（不转发真实 IP） | 免费代理不碰 |
| 验证 | 实验室单机 → 3 次重复 → 7 天灰度 | 全通过才提速 |
| 止损 | 遇 429/验证码/返蜜罐立即熔断 | 弃会话/IP，勿硬扛 |

## §6 标签体系（领域 - 平台 - 难度 - 主题 四级）

标签用于检索与语义匹配，**四级组合、固定顺序、`/` 分隔**：`领域/平台/难度/主题…`。每个条目至少 3 级（领域/平台/难度），主题 1-3 个。

**一级 · 领域**（= 六维 + 扩展，必选 1）：签名 / 参数加密 / 设备指纹 / 环境检测 / 请求策略与行为画像 / 业务规则风控 / 防御侧 / 其他

**二级 · 平台**（必选 1）：Android / iOS / Web / 小程序 / 跨平台
> 取「实测/验证平台」；原理与客户端平台无关（行为层/IP 层）或已在 ≥2 端验证才用「跨平台」，并写「平台适配」字段（general-principles.md §0.10）。

**三级 · 难度**（必选 1）：入门 / 进阶 / 高级

**四级 · 主题**（受控词表，1-3 个）：节奏 / 频控 / IP代理 / 出口治理 / 数据中心 / 灰名单 / 隧道 / 蜜罐 / 数据校验 / 埋点 / 心跳 / 状态机 / 行为熵 / 时空轨迹 / 关联图谱 / 去关联 / 行为路径 / 指纹提取 / 自洽 / 硬件 / 传感器 / TLS / TCP/IP栈 / HTTP头 / UA / 模拟器 / 沙箱 / 多开 / Root / 框架 / Hook / 反Frida / ELF / 注入时机 / 签名比对 / 路径规则 / 封禁 / 接口分层 / 采集面 / 灰度 / 监控 / UI自动化 / 序列 / 参数完整性 …

**命名规范**：
- 中文词不加空格与标点，不用「与/及」连接词（不同主题用 `/` 分隔）；
- 英文技术词保留官方大小写（Frida / Hook / Root / TLS / IP / UA）；
- 同义词只保留一个：`代理IP → IP代理`、`路径级频控 → 路径规则`。

**新增规则**：写新标签前先查词表——语义相同用已有词；确属新主题才新增，并在上方词表登记（附日期与首个使用条目编号）。
**同义合并规则**：发现两词同义 → 保留使用频次高 / 更短者，批量替换全部条目，并在词表标注合并记录（`旧词 → 新词`）。

**标准检索路径（4 步）**：① 定平台 → ② 定领域（六维）→ ③ 定难度 → ④ 主题词过滤 → 读命中条目正文（含「关联」跳转）。
**排查指引（无结果时按序自查）**：平台词是否该用「跨平台」→ 主题词是否过细（换上位词）→ 是否已并入其它条目（版本 >v1.0 的条目有补充内容）→ 是否已作废（索引状态列）→ 均否即知识盲区，触发 SKILL.md A1.5 搜索补录。

示例：`设备指纹/Android/进阶/自洽`、`请求策略与行为画像/Web/入门/IP代理/灰名单`、`请求策略与行为画像/Android/进阶/IP代理/数据中心/路径规则`。

## §7 策略转脚本交付模板（落地执行）

「本 skill」= risk-control-adversary 的**方法论 + references/ 知识库**（不是脚本库）。条目「落地工具」中的「本 skill 策略 → 脚本实现」指：按本模板产出**脚本参数配置表**作为交付物（详见 general-principles.md §0.11）。

**交付标准**：① 每条策略必须映射到脚本参数；② 参数必须有默认值与变异范围；③ 每个熔断信号有处置动作；④ 按 A3.5 验证闭环跑通后才算交付。
